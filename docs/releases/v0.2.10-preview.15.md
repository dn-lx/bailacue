**Renaming is now optional and off by default.** Connecting a source, refreshing it and automatic discovery retain its actual filenames. Existing numbering registries do not enable automatic changes after upgrading.

- **Rename existing videos…** on each source card shows a preview. Apply numbered filenames explicitly starts the pass. Cancel keeps filenames. Only reviewed files are changed; new arrivals wait for a later action.
- **Visible progress and failures:** see checked/renamed/already numbered/pending counts and each file's error. Pause after the current video, then Review remaining renames to retry. Successful files are not renamed repeatedly. Actual observed filenames remain visible on failure.
- **Number new uploads** is a separate per-source setting, off by default. Enable it if future uploads should use `0001.mp4`, `0002.mp4`, and so on. Otherwise uploads keep their chosen title. Enabling this setting does not rename existing videos or outside additions.
- Numbering keeps the video extension and uses no descriptive suffix. Each source retains its own incremental registry and stable video identities. Ratings, labels, notes and practice history stay attached. Matching BailaCue phone copies change only through the explicit action.
- Saved upload sessions/IDs remain recoverable. Rename progress and per-file errors stay on the device rather than entering metadata snapshots.

Earlier builds renamed sequentially as part of discovery, without showing an active per-file job. A source could therefore look refreshed while its filename changes were still running. This release separates discovery from the reviewed rename action.
