# BailaCue 0.2.17 · Android preview build22

Implements the approved review-document changes alongside the blue/black BC-play
identity. Install this APK over the existing preview to preserve your device library.
Source renaming remains optional and off by default.

- Player: supported TextureView mirroring, drag/accessible resize, simplified
  controls, details directly below playback, expandable extras and unified notes/moments.
- Library: shared custom dance types, grouped label suggestions, exact multi-star
  and Unrated filters, source/phone/online filters and persistent numeric/date/rating/title sorting.
- Daily Picks: one per selected dance by default, advanced source mode, rating-first
  eligibility, optional label gates, unrated as5★, direct ratings and no More/Less/Learned controls.
- Practice: filtered, weighted, dance-balanced queue; continuous playback, real
  Previous/Next, saved A–B loops, active-time timer, breaks, safe pause/restore and history.
- YouTube: manual public videos/playlists, preview and selection, deduplication,
  refresh and the owner’s optional Bachata Tutorials suggestion. Opt in separately
  for Daily Picks and Practice. Supported official embedded player; Open in YouTube fallback.
- Branding: vector/outlined masters, transparent and monochrome logos, adaptive/themed
  Android artwork, iOS, splash, favicon, badge and social exports committed with a manifest.

YouTube stays online and cannot be downloaded, mirrored, uploaded, renamed or trimmed
in BailaCue. Complete playlist pagination requires a YouTube Data API key (Advanced
setup); without it the visible player can offer a limited list, disclosed before import.
Playback depends on internet access, creator permissions and YouTube autoplay policies.
No YouTube key, account password or cloud token is included in Git or account sync.

Validation: 185 unit/database tests, 10 browser journeys, typecheck/lint, web export
and Expo Doctor20/20 pass. All 14 Google ARTEMIS native checks pass on the exact
published APK, including real Mirror pixels, resize/trim, separate MP4 export,
original integrity, Photos, labels, Daily Picks and Practice pause/background resume.
The fresh unsigned iOS simulator compile and iOS-target Hermes export pass.

Published APK: 69,090,235 bytes, version0.2.17/build22, unchanged preview signer.
SHA-256: `5249c1458f2719fbb4bcdb45497d418e150c7f28e3e092af25b9b78b463e173d`.
The public download matches the accepted build; APKv2 signature/content digests,
package/version and the public checksum were independently checked.

YouTube/Dropbox browser integration tests mock official endpoints. A live YouTube
attempt was blocked by this environment's network; live creator/autoplay behavior,
provider transfers and physical iPhone runtime remain separate acceptance. Signed
iPhone installation requires Apple signing. This is an internal Android preview,
not a store-signed production release. See docs/VERIFICATION.md for evidence.

Build18 was cancelled before publication after the final review found that optional total-count Daily Picks could include an unselected dance. This build enforces dance selection as an eligibility gate in both modes.

Build19 was cancelled before publication for the final UI/error-state corrections: single YouTube video titles are displayed read-only during import, full-screen controls have a theme-aware backdrop, and Practice clears stale phone-copy references when access is revoked.

Build20 was not published: ARTEMIS detected a black inline frame. Android cannot attach two VideoViews to one player; an invisible full-screen view was taking its surface. Full-screen video is now mounted only while visible. The pixel assertion remains a release gate.

Build21 was withheld after ARTEMIS exposed a Practice pause/state race. Playback events now carry a session/mount identity, stale events cannot change the next video, pause intent stays authoritative, and metadata-only updates keep the preview queue stable. Regression tests cover stale native events and controlled official YouTube pause behavior.

Build22 initially stopped when a harness scroll hit the import preview seek controls. A margin-scroll harness correction retested the same APK; all 14 assertions passed. Recovery publication verified the acceptance hash before publishing.
